## 这是什么

给 AstrBot 装一个"小本本"：她自己记事情，也自己学怎么说话。

四个能力，各自独立、可以单独关掉：

| 能力 | 记什么 | 怎么用上 |
|---|---|---|
| **身份映射** | 平台 ID → 当前名字（曾用名只用于查找，不显示） | 每轮给一行"正在和谁说话" |
| **人物档案** | 关系、印象、备注、初遇地点 | 被问到时用工具查，不再每轮播报 |
| **梗库** | 黑话、谐音梗、抽象梗（释义/出处/例句） | 消息里出现该词才注入，每条计数 |
| **每日日报** | 每天的外部消息：AI/科技、二次元/游戏、大众热点 | 每批每个会话交付一次，细聊时按关键词检索 |

> **长期记忆不在这里。** 记忆的写入、检索和被动注入交给 RAG 插件；本插件只做 RAG 做不了的事：
> 认人（ID→名字）、关系、梗、日报。两个插件同时注入同一类内容只会互相污染。

## 每轮对话她实际看到什么

注入是**临时拼接**的：每次请求重新生成，拼进 system prompt，**不会写进会话历史**，所以不会随对话轮数累积。

优先级从高到低：

| 顺序 | 块 | 何时出现 | 上限 |
|---|---|---|---|
| 1 | `<梗/黑话释义>` | 消息里命中梗库的词 | `glossary_inject_limit` = 3 条 |
| 2 | `<当前对话者 ID=… 名字=…>` | 每轮都给 | 一行 |
| 3 | `<群聊近况>` | 群聊且最近有人说过话 | `group_context_lines` = 3 人，每人 1 条，≤20 字 |
| 4 | `<每日简报>` | 该批还没在这个会话里给过（每批每会话只给一次） | 整批条目（标题+一句），约 300-500 字 |

`<群聊近况>` 只给事实（谁、ID、说了什么），不含任何"该怎么回"的要求——它是用来防止把别人的事记到当前对话者头上，不是用来教她说话。

实测一轮全开约 **250-600 字（≈200-500 tokens）**，比一条普通图片描述还便宜。

几个刻意的设计：

- 关系块只给"正在和谁说话"，档案细节被问到时才查（以前把称呼/印象/曾用名全塞进去，
  她会把别人的事迹套到当前对话者身上，还会追问"你为什么改名"）
- 不写任何"该怎么说话"的要求，只给事实
- 检索没结果时，工具返回里带一句"不代表你不知道，优先依据上下文"

## AI 能用的工具（7 个）

| 工具 | 用途 |
|---|---|
| `update_relationship` | 写入/更新人物档案（昵称、关系、印象、备注、初遇地点） |
| `search_relationship` | 模糊找人（旧名字也能查到） |
| `get_all_relationships` | 列出所有档案 |
| `delete_relationship` | 删除档案 |
| `search_digest` | 查最近新闻/科技/二次元/热点（按关键词） |
| `get_digest` | 看某一天的完整日报 |
| `write_journal` | 在笔记本里写一条（只写不读，不会进上下文） |

工具查不到东西时**不会装作失忆**——返回里会带上兜底提示，避免模型回"我没有记录"。

## 记忆：交给 RAG 插件

这个插件**不再注入长期记忆**。同一套上下文里如果同时有 RAG 插件的被动注入，
两个来源会互相污染（重复、冲突、认错人）。分工是：

| 谁 | 管什么 |
|---|---|
| RAG 插件 | 记忆的写入、检索、被动注入 |
| 本插件 | 身份映射、关系档案、梗库、每日日报 |

`memories` 表和历史数据仍然保留，面板可查，但不再自动注入，也不再提供记忆工具。

## 笔记本：能写，但不能翻旧账

`write_journal` 让她能把想记的事写下来（今天发生什么、答应过什么、此刻的想法），
存在 `memories` 表的"日记"分类里，面板「记忆宫殿 → 看日记」可以按时间翻。

关键设计：**只写不读**。

- 不注入：日记永远不进上下文
- 不检索：没有读取工具，她想不起来也不会去翻
- 不计入记忆：分类是"日记"，重要度固定 1，不参与任何匹配

所以它写坏了也不会有后果——最多是笔记本里多一条废话。它服务的对象是
**你**（你想知道她记了什么），不是她的记忆。

如果哪天想让她能翻，再加一个"按日期读取"的工具就行；但默认不做，
因为"她自己去翻旧账"正是之前反复复读的来源。

## 梗库：自己收集网上的新词

- 数据源（公开热榜，无需登录）：B站热门、B站热词、百度热搜、头条热榜
- 每 `glossary_collect_interval_hours`（默认 **72 小时**）跑一次，每次最多入库 `glossary_collect_max_per_run`（8）条
- 用 LLM 提炼：**必须**给出释义、出处/场景、例句；标题党、空解释、编造的一律丢弃
- 去重三层：规范化精确匹配 → 编辑距离（相似度 ≥0.75 合并）→ 存量批量扫描
- 命中计数：只统计**真正注入**的条目（超上限被丢弃的不算），卡片显示 `命中 N`

## 每日日报：让她跟得上外面的世界

模型自己的知识是停在做训练那天的。日报就是给她补上"今天外面发生了什么"。

**抓什么**（全部公开接口，不用 API key）：

| 源 | 类型 |
|---|---|
| 量子位 RSS | AI / 大模型 |
| 游研社 RSS、机核 RSS | 二次元 / 游戏 |
| B站动画分区、B站游戏分区 | 二次元 / 游戏 |
| 百度热搜、头条热榜 | 大众热点 |

**怎么跑**：

1. 每天 `digest_hour`（默认 **9 点**）跑一次，同一天只跑一次
2. 逐源独立抓取——某个源挂了只跳过它，**全挂就跳过当天，不写空记录**
3. 交给模型挑出 `digest_items_per_day`（默认 **12**）条，每条给出：标题、一两句摘要、关键词、分类、**好聊程度 1-5**
4. 存进 `daily_digest` 表；同时**每条写一条记忆**（分类「每日日报」，重要度 3）——这样她"知道自己看过什么"

**三层用法**（存得厚、看得薄、聊到才取）：

| 层 | 表现 |
|---|---|
| 注入 | 只要**这一批还没在这个会话里给过**，就把整批条目（标题 + 一句摘要）交给她，约 300-500 字；同一批同一个会话只给一次，不会反复念叨。**不看钟点**——她什么时候开口是不确定的，等人来了才给才有用。块上带 `<每日简报 日期=… 来源="系统自动抓取的公开资讯，不是对话内容">`，避免被当成"某人跟她说的话" |
| 记忆 | 聊到相关关键词时，对应的那条自己浮出来 |
| 检索 | `search_digest(关键词)` 找相关条目，`get_digest(日期)` 看某天全部 |

**不会断更**：只要库里没有"今天这一批"，到点后就会补抓（服务器启动晚、昨天失败都能自愈）。

**抓不到怎么办**：

- 每条抓取结果都会记一笔（`digest_runs` 表），面板顶部显示"上次抓取：时间 · 成功/失败原因 · 新增几条 · 用了哪些源"
- 失败不会等一整天：按 `digest_retry_minutes`（30 分钟）重试，成功后就停
- 面板有「立即抓一次」，不用等到 9 点

**不会重复讲同一件事**（全自动，不需要人去登记什么）：

| 机制 | 作用 |
|---|---|
| 注入冷却 | 同一条记忆 `memory_inject_cooldown_hours`（12）小时内只出现一次 |
| **硬上限** | 同一条记忆**最多主动出现 4 次**，之后永远沉底（重要度 ≥7 的豁免） |
| 指数衰减 | 出现 2 次权重减半、3 次剩 1/4，有更相关的内容时自然排到后面 |
| 自动停用 | 对方说"没有这回事""别说了""翻篇"时，上一轮提到的那几条记忆自动停用 7 天 |
| 日报条数上限 | 同一条新闻最多被注入 2 次；跨天按标题近似去重（14 天窗口） |
| 旧数据合并 | 历史遗留的重复日报记忆每天自动合并成一条 |

换句话说：**任何"反复出现但没被真正用到"的内容都会自己消失**，不依赖某个具体词，也不需要有人盯着。

**会自己淡忘**：

- 基础保留 `digest_keep_days`（21 天）
- 被反复提到的（`hits` 高）多留一点，最多再加 `digest_keep_bonus_days`（35 天）
- 到期**归档不删除**，面板勾"含已归档"还能翻到

> 没有向量检索：日报检索走的是关键词 + 命中计数 + 时间衰减。每天 12 条、留一两个月，几百条的规模用 FTS/关键词足够快，不需要引入 embedding。

## 面板

AstrBot 面板 → 插件 → 记忆胶囊。六个标签：

```
仪表盘 ｜ 记忆宫殿 ｜ 关系图谱 ｜ 梗百科 ｜ 日报 ｜ 设置
```

几个实用功能：

- 记忆/梗都支持**多选批量删除**
- 梗库的「检查重复」：预览相似分组，确认后一键合并
- 记忆页「看日记」：只看她写进笔记本的内容
- 记忆页「显示已归档」：查看归档条目并恢复
- 设置页所有改动**立即生效并写盘**（不再是"重启就回退"）

---

## 检索是怎么工作的（不涉及向量）

梗库和日报的检索仍然是关键词 + 命中计数 + 时间衰减：先 FTS5 全文召回，再按标签补一路，
最后按重要度与新鲜度排序。规模只有几百条，不需要 embedding。

长期记忆的向量检索归 RAG 插件，不在本插件范围内。

## 常见问题

**她怎么记不住刚说过的话？**
记忆归 RAG 插件管，先查那边的检索结果；本插件只负责认人、关系、梗和日报。

**为什么群里她会把别人的事说到我头上？**
以前是因为每轮都注入完整档案（称呼/印象/备注/曾用名）。现在只给一行身份，细节改成问到时才查。

**某条记忆突然不出现了？**
记忆归档由 RAG 插件决定；本插件的历史记忆数据仍在面板里可查。

**面板改了设置会丢吗？**
不会，会立即生效并写进插件的配置文件。
